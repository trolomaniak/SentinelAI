## Current architecture

- TASK-012 adds a separate .NET 10 `cloud/ai-gateway` host. It alone reads the model-provider key from gateway cloud configuration and sends structured requests to one fixed verified HTTPS provider origin, with no redirects, no automatic paid retries, strict response validation, body/time/token bounds, authenticated client rate limits and four provider slots. Missing configuration or provider failures return generic unavailable responses.
- Core uses only shared AI contracts and a distinct protected gateway credential. For one selected stored alert it projects the 13 supported rules' allowlisted Boolean/small-integer evidence, rule/severity, Windows platform and coarse observation freshness. IDs, names, raw logs, history, exact timestamps and arbitrary text never enter cloud context. New administrator-only explanation requests accept no client context/destination overrides and require existing effective premium capabilities plus signed `cloud_ai`; Safe Mode preserves all local security workflows.
- AI responses contain explanation, impact, investigation/remediation suggestions and qualitative confidence/uncertainty, labeled assistive. They are not persisted or used to change deterministic detections, scores, alert status or endpoint configuration. The dashboard renders literal text, keeps local review available on failure and ignores obsolete responses after navigation, re-render or session changes. There are no tools or automatic delete/isolate/account actions.
- Agent remains the .NET 10 user-mode Windows Service/console host and self-contained Windows x64 EXE. Enrollment, pinned remote HTTPS, heartbeats, six-hour inventory refresh, and explicit bounded Windows configuration collection remain unchanged.
- Core keeps existing SQLite identity/enrollment/heartbeat/inventory/alert/history persistence and administrator authentication. TASK-009 adds read-only risk APIs computed from one consistent SQLite snapshot of enrolled endpoints, latest inventory, and tracked alerts, using a single explicit evaluation time. No score table or migration is introduced. Relevant status/inventory changes affect the next uncached read.
- `cloud/license-api` is a separate .NET 10 development issuer. It loads a server-only PKCS#8 P-256 private key and startup-validated static entitlements. A random 256-bit activation credential selects a matching organization/Core installation grant via its configured SHA-256 digest; request bodies cannot supply plan, limits, features, or duration. Leases expire exactly seven days after the server UTC issue time.
- `shared/crypto/SentinelAI.Licensing.csproj` contains only the strict compact JWS format and local public-key verification. Protected headers fix ES256 and `sentinelai-lease-v1`; signature covers the header and all required lease claims. Canonical base64url, exact JSON fields, bounded metadata, UTC timestamps, and a positive maximum seven-day lifetime are required. No private-key import or signing implementation is linked into Core.
- Core loads named public SPKI P-256 PEM trust anchors from absolute file paths under `SentinelAI:Licensing:TrustedPublicKeys`. Up to 32 overlapping keys support rotation; unknown settings, private PEMs, other curves, and ambiguous bundles fail configuration. Stateless verification binds both signed IDs to persisted Core identity and keeps valid/expired/invalid/future/identity-mismatch semantics. A separate signature-and-identity authentication method enables trusting signed issuance time before Core applies its effective-time policy.
- TASK-011 adds one non-destructive `LicenseState` table to the existing private SQLite database. It stores the signed lease, signed last-successful-validation baseline, effective UTC high-water and last outcome. Permission reads reauthenticate the stored lease. FULL follows successful current renewal; a failed renewal allows GRACE only before the signed seven-day deadline; missing/expired leases use SAFE_MODE. RECOVERING describes an in-flight request while retaining underlying permissions. Optional signed features are withheld in Safe Mode; all current local security APIs remain available.
- Opt-in `SentinelAI:Licensing:Renewal` configures one fixed HTTPS issuer origin (loopback HTTP for development), protected activation credential path, bounded timeout/interval, and automatic or manual operation. Automatic attempts begin on startup and repeat every six hours by default. Requests use existing identity, no redirects, normal TLS validation, strict bounded replies, and local public-key verification. The signer remains cloud-only; credentials never reach Agent/dashboard/status output.
- Effective licensing time combines wall UTC, signed server issuance, persisted high-water and monotonic runtime elapsed time. Obvious rollback is flagged and cannot revive an expired lease after restart; stale, invalid, unauthorized or expired responses never reset a deadline. Tests stop and restart the real issuer, advance beyond seven days, replay expired material, restart with rolled-back local time, and restore FULL with a fresh signed server response.
- Administrator-only `GET /api/admin/license` and `POST /api/admin/license/renew` expose lifecycle/validation; renewal accepts no client overrides. `GET /api/admin/incidents/export` provides bounded recent incidents/evidence/history from one consistent SQLite snapshot in every mode. New routes retain administrator authentication, HTTPS outside loopback and no-store; renewal is rate-limited. Existing stateless `/license/verify`, cloud issuance, monitoring, enrollment, risk and dashboard contracts remain available.
- `scoring/SentinelAI.Scoring.csproj` provides pure decimal scoring with an immutable validated policy snapshot. Alert contributions expose severity, confidence weight, asset criticality, declared exposure, observation age, status/remediation multiplier, points before mitigation, reduction, and final contribution. Correlation uses distinct supported groups with positive contributions confirmed by the same latest snapshot within the age policy window.
- Default severity points are 1/5/15/25/50; confidence weight is 1; default criticality is standard and exposure unknown, both neutral explicit policy assumptions. Age weights are 1 through seven days, 0.75 through 30 days, and 0.5 thereafter. Open/Investigating/Accepted use status multiplier 1; Resolved uses 0. Default correlation adds five base points per additional group, capped at 20 before asset/exposure multipliers. Raw score, weighted correlation, saturation, and final 0–100 rounded score are explained. Organization score is the highest endpoint score; ties have one bounded representative plus total count.
- `SentinelAI:RiskScoring` configures policy, optional per-endpoint declared criticality/exposure, and inventory freshness (default 12 hours, two inventory cycles). Invalid configuration fails startup. Context sources and the effective policy are exposed; confidence is a policy weight rather than a calibrated probability. Coverage distinguishes missing/unknown/partial/complete inputs for the 13 supported rules, plus stale inventory; it does not certify all Windows protections.
- Administrator-only `GET /api/admin/risk` returns organization/fleet coverage and a bounded ranked endpoint page. `GET /api/admin/devices/{endpointId}/risk` returns full factors/contributions. Both retain existing bearer authentication, HTTPS outside loopback, no-store, and credential separation. Existing device, alert, and current-findings APIs keep their contracts.
- The dependency-free same-origin dashboard adds Risk navigation, ranked endpoint pagination, organization explanation, endpoint factor breakdown, coverage/freshness, raw/capped values, and links from devices/alerts. Browser tokens remain in memory and data is rendered as text. Existing device and alert/status workflows remain available.

## Known issues

- A live model-provider call is not part of local verification: tests use synthetic provider HTTP and generated development credentials. Operators must provision the separate gateway credential/digest, explicit structured-output-compatible model, gateway-only provider key, HTTPS and gateway egress, and review provider retention settings. Model confidence is qualitative and suggestions need human verification.
- GitHub API access currently returns proxy `Forbidden`; the published runtime policy still lacks `api.github.com`. The user resaved the allowed domain setting, but this attached runtime still reports revision 1 with no custom allowed hosts and the actual GitHub API call remains denied. The review branch is `codex/task-012-cloud-ai-v1`; GitHub Actions verification and PR creation remain externally blocked by the active environment configuration.
- Licensing still uses development static grants. Production entitlement/billing, authoritative revocation, automatic trust discovery and enforcement for future premium features/endpoint limits are not introduced. `401` does not prove revocation. No vendor outage or invalid/expired lease stops existing monitoring. The new cloud AI feature uses the existing optional signed feature boundary.
- Rollback protection is bounded: a privileged local account can replace/delete storage; offline powered-off time cannot be inferred perfectly after clock rollback. A large erroneous forward wall-clock jump remains in the persisted floor, so fixing UTC does not authorize replay of a stale lease. Core uses normal HTTPS verification, not a new certificate-pinning/trust distribution system. Windows activation/key files require operator-provisioned account-restricted ACLs; Unix renewal credential permissions are checked directly. Operators still distribute public keys and retain old/new anchors during rotation.
- Scores prioritize reported configuration findings; they do not establish effective protection, Internet exposure, attack probability, or telemetry completeness. A zero rounded score can reflect small positive raw values, explicit confidence discounts, resolved alerts, or missing observations. It never proves safety.
- Criticality/exposure are operator declarations or policy defaults. Confidence weights are not statistically calibrated. The default 12-hour coverage freshness label and seven-/30-day scoring age windows serve different purposes and are exposed separately.
- Scores use current policy and latest positive alert evidence, not historical risk/evidence snapshots. Investigating/Accepted do not remediate risk; Resolved removes its status contribution until newer positive evidence reopens it. Normal/unknown inventory never automatically closes stored alerts.
- Inventory may be stale during outages. BitLocker, live AV health, administrator baselines, and missing-patch indicators still need additional telemetry. No AI or remediation action is introduced by scoring.
- Lost Agent enrollment state still needs an administrator recovery workflow; duplicate enrollment returns `409`. Operators provision HTTPS/certificate pinning. The pre-existing direct `/api/auth/login` endpoint still accepts remote HTTP if Core is explicitly exposed that way; dashboard sign-in and new administrator risk reads reject it.
- Dashboard refresh/reload/expiry behavior remains manual/in-memory. Agent artifacts are unsigned development builds; signed pilot installation belongs to TASK-015. ASP.NET Core's unused key manager may emit its existing generic warning, without persisting a key file.
