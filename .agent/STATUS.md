## Current architecture

- Core supports console and managed Windows Service hosting from the same ASP.NET Core composition root. The signed pilot service installer uses fixed virtual identity, existing protected code/configuration/SQLite locations, explicit automatic/recovery policy and separate protected ownership. Service persistence/admin bootstrap is never profile-dependent or supplied through service arguments. The WPF desktop remains a separate process that does not control Core lifetime. See `docs/ARCHITECTURE.md` and `docs/CORE-SERVICE.md`.

- `desktop/SentinelAI.Desktop` is the Windows-only WPF composition root and native window/view/theme layer; `SentinelAI.Desktop.Foundation` is a separate dependency-free portable MVVM/service assembly. Overview, Devices, Alerts, Risk, Reports and Settings are navigation placeholders rather than migrated dashboard screens. The existing browser dashboard and all Core/Agent contracts remain unchanged.
- Desktop's initial `ICoreClient` implementation only checks the existing fixed `http://127.0.0.1:5000/api/health` route. It sends no credentials, disables redirects/proxy/cookies/default credentials, bounds header/body time to three seconds and JSON to 4 KiB, and renders only generic connection status. No UI input selects a destination. Opening/navigation remains available when Core is absent; closing cancels checks and disposes the client without creating a password/configuration store.
- Semantic dynamic palette/style resources and WPF logical units provide the theme/scaling foundation. The executable requests PerMonitorV2 and runs as the current non-elevated user. Portable tests run through the existing repository script; a dedicated Windows CI job separately checks real WPF views and the published GUI before artifact upload.

- `installer/pilot` installs only explicitly trusted signed fresh packages via the existing bounded public verifier/extractor. Protected Program Files code is separate from ProgramData configuration, SQLite, installation identity and DPAPI enrollment state. New directories receive restricted ACLs atomically; links, hard links, unknown services/state, changed retry code/configuration and unsafe writable paths are refused. The installer never adopts an interrupted installation lacking an ownership receipt.
- The original pilot initializes Core in a loopback console under the operator, with bootstrap credentials only in the newly created child environment; TASK-017 can subsequently register it as a managed service under its own virtual account. Agent stays the automatic `SentinelAIAgent` Windows Service under stable, limited `NT AUTHORITY\LocalService`; that shared account's current-user DPAPI scope is documented. One-use enrollment uses a fixed restricted file removed after durable validation. A nonsecret endpoint receipt derives from persistent enrollment and selects the exact device for fresh heartbeat/inventory/dashboard verification. Service removal preserves all code/configuration/state; identical-package reinstall preserves identity.
- Both hosts support an explicit bounded allowlisted `--config ABSOLUTE_FILE` mode authoritative over ambient host settings, without changing legacy console/environment configuration. Passwords and tokens are excluded from persistent config, service arguments and logs. Updater `prepare` authenticates and extracts a fresh Core/Agent code directory without starting a service or asserting health; bootstrap scripts/verifier and the separate public trust root still require trusted delivery. Transactional upgrade/service integration remains separate from fresh pilot installation.

- `shared/updates/SentinelAI.Updates.csproj` is a separate dependency-free, public-only update library. Bounded exact JSON fixes P-256/SHA-256 over format/key ID and all version/artifact URL/hash/size/channel/environment claims. Explicit locally provisioned public roots and exact environment/channel/artifact/version policy authorize a candidate; signatures, SHA-256, byte length and strictly newer numeric versions are mandatory. Signed installed receipts prevent replay even with a stale caller version floor. Development and production trust are separate from licensing and Agent credentials.
- `updater` locally verifies or stages an immutable private ZIP copy, or prepares a fresh code directory through bounded verified extraction; it does not download packages, control services or replace an existing installation. Separate `tools/update-dev` generates development keys outside repositories and signs only development manifests, with no production mode. The client/library do not import private keys. Stable, Pilot and Beta are distinct explicit channels. No production private key, embedded trust root, dependency, cloud endpoint, existing API change or migration is added.
- The transactional API validates the package and bounded ZIP paths/contents before service stop, then swaps a code-only directory at a stable path using an exclusive lock, sibling backup and durable journal. An explicit cancellable service adapter must start/check the actual service; health gates the signed receipt. Failure/cancellation restores and checks previous code with an independent bounded recovery deadline. Failed rollback retains backup/journal; authenticated recovery handles process interruption between renames and phase writes. Known state files are rejected in code/package; persistent AppData/DPAPI state stays outside code under the same service account. TASK-015 supplies fresh Windows installation/service control; transactional upgrade adapter integration remains outside this pilot workflow.
- TASK-013 adds `SecurityReportReadStore`, explicit report records and a standalone HTML renderer, reusing the existing current risk scorer/coverage logic. One consistent SQLite read snapshot projects selected endpoint/security fields and aggregates the full status history without credentials or actors. Period association is a retained first/latest observation or status transition within inclusive UTC dates; resolutions count distinct incidents even after reopening. Current risk/health/posture are explicitly separate from historical activity, and unavailable score history is never reconstructed.
- Administrator-only `GET /api/admin/reports/security?from=yyyy-MM-dd&to=yyyy-MM-dd` accepts strict ordered ranges up to 366 inclusive days, requires HTTPS outside loopback and returns a no-store/nosniff/CSP-protected HTML attachment. Reporting remains available in Safe Mode without AI, license renewal or cloud access. Fixed work limits are 1,000 enrolled endpoints/13,000 tracked alerts; files above 8 MiB or larger datasets return `422`, while 200-item detailed sections disclose omissions and retain complete admitted aggregate counts.
- Reports UI defaults to the previous complete UTC month and explicitly generates/downloads an HTML Blob without injecting it into the dashboard or putting tokens in URLs. Downloads are cleared/revoked after replacement, navigation, signout and session expiry; stale session/navigation responses are ignored. Local rule templates and allowlisted Boolean/bounded integer evidence feed fully encoded HTML with no scripts/external resources. Browser printing can save PDF; no renderer service, new dependency, migration, report persistence, scheduler or remediation is added.
- OS inventory adds optional `OsDisplayVersion` and `OsInstallationType`; `OsVersion` remains the numeric build. Core returns an additional optional detail `OsName` and combines observed release/type/build for display. Core bounds optional metadata; no database migration, dependency, security configuration change or AI-context expansion is introduced. The redundant client type is suppressed to match the requested display; meaningful server type remains. Missing release metadata stays unknown rather than being inferred from a build number.
- TASK-012 adds a separate .NET 10 `cloud/ai-gateway` host. It alone reads the model-provider key from gateway cloud configuration and sends structured requests to one fixed verified HTTPS provider origin, with no redirects, no automatic paid retries, strict response validation, body/time/token bounds, authenticated client rate limits and four provider slots. Missing configuration or provider failures return generic unavailable responses.
- Core uses only shared AI contracts and a distinct protected gateway credential. For one selected stored alert it projects the 13 supported rules' allowlisted Boolean/small-integer evidence, rule/severity, Windows platform and coarse observation freshness. IDs, names, raw logs, history, exact timestamps and arbitrary text never enter cloud context. - AI responses contain explanation, impact, investigation/remediation suggestions and qualitative confidence/uncertainty, labeled assistive. They are not persisted or used to change deterministic detections, scores, alert status or endpoint configuration. The dashboard renders literal text, keeps local review available on failure and ignores obsolete responses after navigation, re-render or session changes. - Core keeps existing SQLite identity/enrollment/heartbeat/inventory/alert/history persistence and administrator authentication. TASK-009 adds read-only risk APIs computed from one consistent SQLite snapshot of enrolled endpoints, latest inventory, and tracked alerts, using a single explicit evaluation time. No score table or migration is introduced. Relevant status/inventory changes affect the next uncached read.
- `cloud/license-api` is a separate .NET 10 development issuer. It loads a server-only PKCS#8 P-256 private key and startup-validated static entitlements. A random 256-bit activation credential selects a matching organization/Core installation grant via its configured SHA-256 digest; request bodies cannot supply plan, limits, features, or duration. Leases expire exactly seven days after the server UTC issue time.
- `shared/crypto/SentinelAI.Licensing.csproj` contains only the strict compact JWS format and local public-key verification. Protected headers fix ES256 and `sentinelai-lease-v1`; signature covers the header and all required lease claims. Canonical base64url, exact JSON fields, bounded metadata, UTC timestamps, and a positive maximum seven-day lifetime are required. No private-key import or signing implementation is linked into Core.
- Core loads named public SPKI P-256 PEM trust anchors from absolute file paths under `SentinelAI:Licensing:TrustedPublicKeys`. Up to 32 overlapping keys support rotation; unknown settings, private PEMs, other curves, and ambiguous bundles fail configuration. Stateless verification binds both signed IDs to persisted Core identity and keeps valid/expired/invalid/future/identity-mismatch semantics. A separate signature-and-identity authentication method enables trusting signed issuance time before Core applies its effective-time policy.
- TASK-011 adds one non-destructive `LicenseState` table to the existing private SQLite database. It stores the signed lease, signed last-successful-validation baseline, effective UTC high-water and last outcome. Permission reads reauthenticate the stored lease. FULL follows successful current renewal; a failed renewal allows GRACE only before the signed seven-day deadline; missing/expired leases use SAFE_MODE. RECOVERING describes an in-flight request while retaining underlying permissions. Optional signed features are withheld in Safe Mode; all current local security APIs remain available.
- Opt-in `SentinelAI:Licensing:Renewal` configures one fixed HTTPS issuer origin (loopback HTTP for development), protected activation credential path, bounded timeout/interval, and automatic or manual operation. Automatic attempts begin on startup and repeat every six hours by default. Requests use existing identity, no redirects, normal TLS validation, strict bounded replies, and local public-key verification. The signer remains cloud-only; credentials never reach Agent/dashboard/status output.
- Effective licensing time combines wall UTC, signed server issuance, persisted high-water and monotonic runtime elapsed time. Obvious rollback is flagged and cannot revive an expired lease after restart; stale, invalid, unauthorized or expired responses never reset a deadline. Tests stop and restart the real issuer, advance beyond seven days, replay expired material, restart with rolled-back local time, and restore FULL with a fresh signed server response.
- Administrator-only `GET /api/admin/license` and `POST /api/admin/license/renew` expose lifecycle/validation; renewal accepts no client overrides. `GET /api/admin/incidents/export` provides bounded recent incidents/evidence/history from one consistent SQLite snapshot in every mode. New routes retain administrator authentication, HTTPS outside loopback and no-store; renewal is rate-limited. Existing stateless `/license/verify`, cloud issuance, monitoring, enrollment, risk and dashboard contracts remain available.
- `scoring/SentinelAI.Scoring.csproj` provides pure decimal scoring with an immutable validated policy snapshot. Alert contributions expose severity, confidence weight, asset criticality, declared exposure, observation age, status/remediation multiplier, points before mitigation, reduction, and final contribution. Correlation uses distinct supported groups with positive contributions confirmed by the same latest snapshot within the age policy window.
- Default severity points are 1/5/15/25/50; confidence weight is 1; default criticality is standard and exposure unknown, both neutral explicit policy assumptions. Age weights are 1 through seven days, 0.75 through 30 days, and 0.5 thereafter. Open/Investigating/Accepted use status multiplier 1; Resolved uses 0. Default correlation adds five base points per additional group, capped at 20 before asset/exposure multipliers. Raw score, weighted correlation, saturation, and final 0–100 rounded score are explained. Organization score is the highest endpoint score; ties have one bounded representative plus total count.
- `SentinelAI:RiskScoring` configures policy, optional per-endpoint declared criticality/exposure, and inventory freshness (default 12 hours, two inventory cycles). Invalid configuration fails startup. Context sources and the effective policy are exposed; confidence is a policy weight rather than a calibrated probability. Coverage distinguishes missing/unknown/partial/complete inputs for the 13 supported rules, plus stale inventory; it does not certify all Windows protections.
- Administrator-only `GET /api/admin/risk` returns organization/fleet coverage and a bounded ranked endpoint page. `GET /api/admin/devices/{endpointId}/risk` returns full factors/contributions.
