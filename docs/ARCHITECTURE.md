# Core hosting and desktop lifetime

Core is the existing .NET 10 ASP.NET Core host with SQLite persistence. Console/development hosting remains available. On Windows, the official WindowsServices host integration connects Core to SCM as `SentinelAICore`; it uses the executable's directory for content and requires the explicit, bounded, nonsecret `--config` file. Service mode refuses bootstrap credentials and first-run administrator creation. The console launcher or Desktop's Core-owned local setup command initializes the administrator before service registration.

The installer manages delayed automatic startup and a fixed limited virtual account, `NT SERVICE\SentinelAICore`. Code remains under protected Program Files and the existing pilot configuration/database remain under ProgramData. The service has read/execute access to code, read access to configuration and ownership receipts, and narrowly scoped runtime-data write access. Agent's LocalService identity, DPAPI state and enrollment rules are unchanged. A separate protected Core service receipt binds the SCM registration to the pilot installation; unknown registrations are refused.

Core and the WPF desktop are separate processes. Opening or closing the desktop does not control the Core service. Core's existing `/api/health` response is available after hosted persistence initialization, and service installation/start verifies both SCM state and the configured loopback health listener. Graceful service stop uses the host cancellation lifecycle with a 15-second shutdown budget. SCM crash/failure recovery uses bounded restart delays; ordinary operator stop does not request recovery.

The supported installer configuration remains loopback HTTP, with the existing HTTPS requirements preserved for other console deployments. No schema migration, administrator replacement, remote listener, certificate provisioning, secret-bearing service command or transactional upgrade integration is added. See [Core service operation and validation](CORE-SERVICE.md) and [pilot package trust](PILOT.md).

# Desktop authentication

The WPF shell uses a portable authentication state model and Core's existing login/session authority. Bearers remain private in memory, refresh tokens are discarded, and passwords are never model-bound or persisted. Sign-out invalidates pending completions; expiry, `401`, restart or connection loss closes the local session. Workspace navigation is gated behind authentication.

First-run detection and creation use one-shot commands in the trusted installed Core executable against the existing protected configuration. Creation accepts bounded credentials through private redirected stdin, uses the same hasher/atomic SQLite transaction, and cannot replace an administrator. The helper starts no HTTP listener. UAC is confined to a separate initial-setup window when required; normal sign-in remains unelevated and does not require access to SQLite or protected setup files.

SCM's administrator-controlled registration identifies the managed Core process. The native authentication transport verifies ownership of the actual connected TCP tuple before HTTP can write secrets, closing the port-occupation race of a simple pre-request listener check. Console fallback retains existing operator filesystem trust. Service identity/ACL/bootstrap policy remain unchanged, and remote plaintext login is rejected before credential body binding. See [desktop authentication](DESKTOP-AUTH.md).

# Native Desktop devices

Devices uses read-only administrator API calls through the same private authentication client and connected-peer-verified transport. No bearer is exposed to views/view models, and Desktop never reads SQLite or enrollment credentials. Core remains authoritative for healthy/warning/offline/unknown; configured security posture and inventory observation times are displayed separately.

Core's list response adds an optional inventory timestamp derived from the existing stored report. This avoids one detail request per fleet row, with no schema migration or change to existing fields. Desktop validates bounded public DTOs, filters/sorts the complete accepted list, and presents 100-row pages in a recycling native DataGrid. Detail shows only the public typed inventory fields already exposed by Core. Cancellation/generation checks reject obsolete results; sign-out clears all device state. See [native device operation](DESKTOP-DEVICES.md).

# Native Desktop alerts and incidents

Alerts uses the same private authenticated, connected-peer-verified transport for Core's public paged list/detail and versioned status API. An additive optional endpoint filter applies with severity/status before server paging and count, preserving existing defaults and response contracts. The native workspace renders bounded literal typed evidence and the latest retained history with its total disclosed.

Only the administrator's explicit save changes status, using the version reviewed in detail. Conflicts reload current state and require a fresh decision; uncertain write outcomes require a detail refresh before another save, with no automatic write retry. Core owns all persistent lifecycle/history and newer-positive reopening policy; no endpoint configuration changes are performed. Session cancellation and generations prevent obsolete completions from restoring workspace data. See [native incident operation](DESKTOP-ALERTS.md).

# Native Desktop Risk and Reports

Risk consumes Core's existing organization/page and endpoint-detail projections through the private authenticated transport. Portable Foundation references existing immutable `SentinelAI.Scoring` records, preserving decimal values, saturation, all contribution factors, context sources, coverage and effective policy. It never invokes `RiskScorer`; Core supplies ranked 50-row server pages and independently timestamped detail evaluations. Native views render literal text without inventing history or inferring missing observations.

Reports reuses Core's existing privacy-preserving, Safe-Mode-capable HTML generation endpoint. Desktop accepts a bounded strict UTF-8 attachment with Core's required content/cache/CSP headers and keeps exact bytes in an owned disposable memory object. Views expose only period, filename, size and status; generation neither saves nor opens a file. An explicit native picker confirms the `.html` destination/replacement before a same-directory staged write and atomic destination move. Date edits, navigation away, sign-out and close erase retained bytes and invalidate pending operations; already exported documents remain operator-owned. No browser embedding, report recomposition, new history, scorer change, AI dependency or database migration is introduced. See [native Risk/Reports operation and bounds](DESKTOP-RISK-REPORTS.md) and [Core report semantics](REPORTING.md).

# Native Desktop AI and licensing

Settings reads only the existing public Core licensing projection and requests explicit manual renewal without body/query overrides. Selected-alert AI uses the same private authenticated/trusted transport, sends only the stored alert ID and reuses the first-party strict response contract. Core owns all signed state, permissions, context minimization and fixed issuer/gateway configuration; no Core production contract, migration or dependency changes.

Session-only local consent defaults off and resets on sign-out/close, while navigation preserves the preference and erases obsolete analysis. Consent, supported evidence and current public entitlement gate explicit AI requests; Core enforces them authoritatively. Bounded literal results, generic failures, cancellation/generation guards and UI-dispatched cross-view updates keep optional failures independent of local Alerts/Risk/Reports and prevent stale expiry or lock inversion. Settings also exposes fixed local runtime facts and the existing health check. See [native AI/licensing operation](DESKTOP-AI-LICENSING.md).

# Continuous posture monitoring

The Agent watches exactly the registry keys its configuration collector reads, using one-shot Windows change notifications plus a five-minute verification fallback. Notifications are coalesced into one signal slot and trigger a settled re-read of the same bounded allowlist. A posture that differs from the one Core last acknowledged becomes a single pending delivery. A reachable, enrolled heartbeat worker then sends a fresh full inventory through the existing authenticated route, spaced at least 30 seconds after the previous upload.

Core, the inventory contract, the rules, alert lifecycle and Risk computation are unchanged; Core still stores only the newest report. The independent six-hour inventory remains reconciliation, and startup reconciliation covers changes made while the Agent was stopped. Nothing is queued or persisted for retries. Outages keep the existing heartbeat backoff, and a failed upload keeps the five-minute retry. See [posture monitoring operation and bounds](POSTURE-MONITOR.md).

# Continuous Windows security event pipeline

The Agent reads a compiled catalog of 16 Windows security events from the Security, System, PowerShell/Operational and Defender/Operational channels. One background loop checks each channel's record range every five seconds and reads new records with a catalog-generated `EventLogReader` query that also selects the channel's position, seeks on it and verifies its creation time to detect clears. Selected records are reduced to SIDs, closed vocabularies and bounded names, then delivered in at most one prepared batch through a new authenticated route. A position moves past collected records and gaps only after Core acknowledges them, and nothing is read while a batch is pending, so the Windows channel is the bounded outage buffer. Overwrites, resets, coverage starts and dropped records travel as gap items in the same batch. The loop stays dormant until the heartbeat worker reports an enrolled, acknowledged Agent. Each channel fails separately (`accessDenied`, `notFound`, `error`, retried every minute), and failures never stop the host or affect heartbeats, inventory or posture monitoring. The installed LocalService Agent reports Security as `accessDenied`; any read grant awaits a security-boundary decision.

Core authenticates the Agent before reading the body, parses at most 256 KiB with strict JSON options and validates each item separately: unknown items are ignored and invalid ones rejected, and an invalid observation is recorded as a `rejected` gap. One immediate SQLite transaction stores observations once per endpoint, channel, record number and event time, merges gaps, flags a coverage start on an already covered channel as a coverage restart and keeps the latest status per channel. Retention is 10,000 observations and 1,000 gaps per endpoint and 30 days by receipt time. Administrators read only states, counters, record numbers and gap metadata through a status route; rules, alerts, reports and AI do not use the observations yet (TASK-028). See [security event collection, bounds and runbook](SECURITY-EVENTS.md).
